## 接口和计时

```python
from rknn_bridge import RknnSession
from model_adapter import adapt_outputs
from yolo_common import postprocess

with RknnSession(model_path, library_path, detail=False, core_mask=7) as session:
    raw_outputs, api_timing = session.run(rgb_uint8_hwc)
    # 应用后处理计时从这里开始。
    canonical9 = adapt_outputs(raw_outputs)
    detections = postprocess(canonical9, transform, .25, .45, 300)
```

`RknnSession` 无新参数，仍是九输出默认契约。输出顺序是每尺度 `(reg64, sigmoid_class80, clip_sum1)`，尺度依次 80/40/20，batch=1、NCHW；`.run()` 返回独立 float32 数组。`adapt_outputs` 在九路模式验证契约后原样返回输入对象，不再次 Sigmoid。可处理六路的稳定 float32 Sigmoid 代码只做了单元测试，本轮实际模型未使用。

最终模型 PERF_DETAIL 中三个 Sigmoid 均为 `FLOAT16 CPU`，报告 ID 是 74、93、108；求和与裁剪仍是 NPU `ConvClip`。这是该最终模型的实测，不应直接迁移到其他模型。内部 CPU 激活已经包含在 `rknn_run` 中，应用后处理只包含适配验证、DFL/NMS 等，不得把内部 CPU 时间再次相加。详细报告见 `final_cpu_placement.perf.txt`，同图详细模式和正常模式九输出逐元素相同。
