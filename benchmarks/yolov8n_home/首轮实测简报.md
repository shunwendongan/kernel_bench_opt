# RK3588 YOLOv8n 首轮实测简报

实验日期：2026-11-06（中国标准时间）  
实验编号：`yolov8n_home_20261106_01`

已完成模型选型、数据抽样、预处理、RK3588 推理、质量对照及节点热点采集。代码修改前已保存[实现计划](实现计划.md)。本轮交付的是**诊断基线**。严格输出数值门槛未通过，不能标记为正式验收通过。

## 选型与样本

| 项目 | 本轮选择 |
|---|---|
| 任务与模型 | 目标检测；Rockchip 官方部署导出的 YOLOv8n |
| 部署规格 | FP16 非量化，batch=1，640×640，RK3588 内置三核 NPU |
| 数据集 | COCO val2017，固定 seed=42 |
| 抽样 | 瓶、杯、椅、沙发、床、餐桌、电视、笔记本电脑，每类主分层各 5 张，共 40 张 |
| 标注 | 保留入选图片的全部 436 条实例及 crowd 信息 |
| 预处理 | RGB、等比例 letterbox、填充 114、双线性缩放；保存每图缩放和补边参数 |
| 后处理 | CPU 执行 DFL、分类别 NMS、原图坐标还原 |

这批数据是**家庭相关物品子集**。缩略图审查为 35 张室内、5 张室外。室内还包含餐饮、教室和办公空间，未确认真实家庭域。子集 AP 不代表完整 COCO 或家庭产品精度。

ONNX 与 RKNN 使用等价输入。ONNX 输入为 FP32/NCHW，并除以 255。RKNN 提交 UINT8/NHWC，归一化由编译配置处理。40 张原图、实际输入字节及模型哈希均已在板端核验。

模型来源、固定提交和完整哈希见 [SOP](README.md)、[config.json](config.json)。样本来源、图片许可和参考标注索引见 [samples.json](dataset/samples.json)。

## 实测规模与性能

板端 Runtime/Toolkit2 为 2.3.2，NPU 驱动为 0.9.8。正常轮与详细轮采用独立 context。两轮均常驻模型，预热 3 次，申请 NPU core mask=7。CPU 未绑核，OpenCV 与数值库线程配置已记录。

| 采集 | 正式次数 | 运行失败 |
|---|---:|---:|
| ONNX/RKNN 质量对照 | 40 | 0 |
| 正常计时：每图 10 次 | 400 | 0 |
| 详细 profiling：每图 1 次 | 40 | 0 |

正常轮统计如下。单位为 ms。P95 来自这 40 张图片各重复 10 次的混合分布。

| 计时范围 | 平均 | 中位数 | P95 |
|---|---:|---:|---:|
| 读取、解码、预处理 | 8.61 | 6.50 | 19.90 |
| 推理调用整体 | 71.12 | 65.18 | 92.82 |
| DFL、NMS、坐标还原 | 9.92 | 7.85 | 18.08 |
| 端到端 | **89.65** | **88.65** | **120.88** |

推理调用整体包含输入提交、执行、输出获取、复制与释放。其内部平均值为：输入提交 13.19 ms、`rknn_run()` 43.98 ms、输出获取 12.00 ms、输出复制 1.72 ms。`rknn_run()` 是运行库入口计时，不能称为纯 NPU kernel 时间。

正常轮模型创建包围时间为 32.85 ms，单列统计。端到端不含模型加载、哈希、绘图、结果保存和精度评估。图片经过事先读取，未清理 OS 页缓存，因此不属于冷缓存测试。

没有锁定 CPU/NPU/DDR 频率。正常轮快照中的 NPU 为 1 GHz，DDR 出现 528/1068 MHz，CPU 频率也有变化。NPU 温度快照为 40.692～41.615℃。这些离散快照不能证明整段运行状态恒定。当前数据不用于严格性能排名。

## 质量结论：任务指标通过，严格数值门槛失败

| 对照项 | ONNX CPU 参考 | RKNN | 结论 |
|---|---:|---:|---|
| 当前 40 图的 AP@[.5:.95] | 0.36805 | 0.36737 | 绝对下降 0.000685，在原定 0.01 门槛内 |
| 当前 40 图的 AP50 | 0.51576 | 0.51625 | 子集任务指标 |
| confidence=0.25 的检测框数 | 271 | 271 | 同类且 IoU≥0.90 的框匹配 270 个，匹配率 99.63% |
| 输出有限性 | 360 个张量 | 360 个张量 | 全部有限 |
| 每输出相对 L2≤0.02 | — | 120 个通过、240 个失败 | **完整质量门槛失败** |

AP 评估使用 confidence=0.001、NMS IoU=0.65，显式覆盖全部 40 个 image_id 及全部类别。检测框匹配使用 confidence=0.25、NMS IoU=0.45。两种阈值的用途不同。

三个框回归输出通过数值门槛。三个分类输出及三个分数求和输出失败。40 张图的分类输出均出现最小值 `0.0018310546875`，分数求和输出均出现最小值 `0.146484375`。大量背景概率接近零，导致相对 L2 被放大。该现象不能仅用 FP16 舍入误差解释，也不能据此断言厂商内部采用了某种近似算法。

对样本 430286，官方 Lite2 与当前 C API 桥接程序九路输出逐元素相同。三个采集模式各自保留的 40 张图首次正式输出也完全相同。这排除了桥接程序独有差异，以及本轮详细采集对所保存输出的数值影响。

原定门槛未修改。质量汇总程序退出码为 2，失败证据已保留。后续性能采集明确标为诊断。详见 [verification.json](runs/verify_01/verification.json)、[output_diagnostics.json](evidence/output_diagnostics.json) 和 [采集范围说明](evidence/diagnostic_policy.json)。

## 算子热点与优先方向

40 份报告均严格绑定同一 RKNN 文件的真实图：**108 个编译节点、257 个张量、138 条张量依赖边**。其中 98 个节点标记为 NPU，10 个为 CPU；CPU 节点均为模型输入/输出节点。模型外预处理和后处理不在此节点表中。

详细轮节点时间之和平均为 61.42 ms。下表仅描述该详细轮，不与正常轮拼成同一条时间线。

| 编译节点类型 | 数量 | 平均累计 ms | 详细节点时间占比 |
|---|---:|---:|---:|
| ConvExSwish | 57 | 46.00 | 74.89% |
| Concat | 13 | 5.81 | 9.46% |
| Split | 8 | 3.09 | 5.02% |
| Add | 6 | 1.81 | 2.95% |

按模块名称建立候选组，再按真实张量依赖拆分连通分量。每图保留前四个不重叠热点，共 **40 行样本记录、160 个热点实例**。

| 热点组 | 进入前四的图片数 | 入选时平均节点耗时 ms |
|---|---:|---:|
| model.2 | 40 | 8.01 |
| model.4 | 39 | 6.85 |
| model.15 | 39 | 5.19 |
| model.6 | 20 | 4.65 |
| model.22#2 | 21 | 4.34 |
| model.0 | 1 | 4.07 |

表中均值仅针对该组入选的图片，不能当作统一样本集上的独立子图基准。`model.22#2` 对应第一尺度分类分支的连通部分。节点与边界张量索引见 [RK3588Bench.jsonl](RK3588Bench.jsonl) 和 [共享编译图](graphs/compiled_graph.json)。

后续建议按以下顺序推进：

1. 先核查分类输出的数值差异。按输出含义制定绝对误差、相对误差和任务指标协议，再用新样本验证。保留本轮失败，不追认通过。
2. 补充经过场景确认的家庭数据。将当前 40 图保留为复测集，不因结果换图。
3. 优先研究 `model.2`、`model.4` 的卷积与 Split/Concat 结构，以及 `model.15`。热点结构与计时均已有证据。
4. 同时检查输入提交、输出获取和 CPU 后处理。正常轮 `rknn_run()` 约占端到端均值的 49.05%，单看计算节点会遗漏其他开销。
5. 在保持质量与输入一致的前提下，固定硬件状态后复测候选优化。当前尚未实现或证明算子加速收益。

没有捕获内部热点边界张量值。所有热点均标记 `subgraph_io_available=false`、`replayable=false`。内部算子库 API、设备任务时间线、能耗及跨后端成本矩阵尚未采集。
