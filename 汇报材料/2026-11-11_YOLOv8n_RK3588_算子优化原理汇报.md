# YOLOv8n · RK3588 算子优化原理汇报（2026-11-11）

面向小组汇报的原理说明，配合 2026-11-06 的 13 页基准汇报使用。本页只讲“热点在哪里、为什么这样改、改完怎么验收”；所有板端收益都尚未测量，开发机数字只说明方向。

## 1. 一张图的时间去了哪里（首轮正常轮均值，ms）

```
读取解码+letterbox 8.6 │ inputs_set 13.2 │ rknn_run 44.0 │ outputs_get 12.0 │ 复制 1.7 │ numpy 后处理 9.9  ＝ 89.7
                       └─ 运行库把 uint8 转成 fp16 ─┘            └─ 运行库把 fp16 转回 fp32 ─┘
```

- 约 37 ms（41%）是宿主侧的格式转换和 Python 后处理，与 NPU 计算无关。
- 为修数值问题引入的 CPU Sigmoid 在最终模型里又加了 24.5 ms（PERF_DETAIL 单帧 81.6 ms 的 30%）。
- NPU 本体：57 个 ConvExSwish 43.5 ms；Concat 5.1、Split 2.9、Add 1.8；茎部 `model.0` 4.1 ms 但算力利用率 0.7%。

## 2. 七个候选，三类杠杆

| 类别 | 候选 | 原理一句话 | 预期杠杆（已有证据口径） |
|---|---|---|---|

|  | 04 pre-letterbox-neon | 与 cv2 INTER_LINEAR 逐字节一致的定点 letterbox，直接写进 fp16 输入缓冲 | 8.6 ms 中的预处理部分 |

把 01～04 叠加的粗算：推理链路有机会从约 90 ms 降到 50 ms 以下，`rknn_run` 约 44 ms 成为新的瓶颈。这是推断。

## 3. 三个关键原理

### 3.1 Sigmoid 可以搬到宿主而且只做 1/80

后处理只需要每个 anchor 的最大类别概率与类别号。Sigmoid 单调递增，所以 `argmax σ(x) = argmax x`、`max σ(x) = σ(max x)`：8,400 次而不是 672,000 次。概率张量只在质量验收导出时整张计算（NEON，float32），门槛不变。数值反而更好：CPU FP16 Sigmoid 的输出被舍入到 fp16（p≈0.5 时 ulp 4.9e-4，正是通用轮 RMSE 5.5e-4 的来源），宿主 float32 Sigmoid 只承受 logits 的 fp16 舍入。

### 3.2 卷积按输出通道切片是免费的

`Split(Conv(W,b)(x)) ≡ (Conv(W[:c′],b[:c′])(x), Conv(W[c′:],b[c′:])(x))`。每个输出通道只用自己那一行权重，SiLU 逐元素；总乘加不变，Split 的一读一写消失，Concat/Bottleneck/残差全部不用改。ORT 验证 9 路输出逐位相同。

### 3.3 零拷贝的前提是宿主能产出原生格式

模型输入是 fp16 NHWC，输出是 fp16（原生布局通道/宽度补 8）。首轮桥接提交 uint8、取 float32，于是运行库每帧转两次。桥接 v2 用 `rknn_create_mem`/`rknn_set_io_mem` 绑定一次，letterbox kernel 直接写 fp16（uint8→fp16 精确，归一化已折进第一层卷积），后处理 kernel 直接在 fp16 NCHW/NC1HWC2 视图上扫描。质量验收导出的 float32 与首轮 `want_float` 必须逐位相同，这是 L2 的硬检查。

## 4. 不变量与验收

- 预处理字节：与冻结的 40 张 `dataset/inputs/*.u8` 哈希一致（开发机已与 cv2 逐字节一致）。
- 后处理语义：类别/分数逐位相同，框 ≤ 2e-3 px；并列次序按 numpy 规则。
- 数值门槛：`quality_protocol.json` 不变；logits6 经 float32 Sigmoid + 求和裁剪还原后进门槛。
- 评测分级：L1 kernel 对拍与微基准 → L2 旧桥接 vs 新桥接 40 图逐位/检测/哈希/门槛 → L3 40 图 × 10 次端到端（口径与首轮正常轮相同）。
- 失败处理：任何门槛失败保留记录，候选标 `rejected_*`，不调门槛。
